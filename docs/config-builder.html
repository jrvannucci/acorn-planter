ACORN config builders

Three standalone pages that fill in ACORN's three configuration files from a form, explain every field, and run the same checks acorn does. Each is self-contained — no network, opens straight off a USB stick with file://. None of them install, build, or change anything; they produce text you commit into your distributed copy of the repo.

Three files, then one command.

global.conf — where every machine looks: the source repo, the package index, the Python mirror, the editor build. Read by both installers at install time.

installation-profile/*.toml — what each group of users ends up with, and who gets it: interpreters, venvs, packages, repos. Read by acorn apply.

offline-bundle.toml — what an air-gapped share holds: the superset every profile must be a subset of. Read by the offline bundler.

A standard internet install needs none of them. You add them to deploy ACORN to a team, an internal network, or a fully disconnected one.

global.conf builder

The 19 ACORN_* keys, grouped and documented. Import an existing file, edit, re-export. Optional cross-check against an offline bundle's editor settings.

profile builder

A folder of deployment profiles: distribution rules, venvs, packages, repos, [config]. "Who gets what" resolver. Optional fit-check of every profile against a pasted offline-bundle.toml.

offline bundle builder

Platforms, interpreters, the wheelhouse, conda-forge tools, the editor, build settings. Import/validate/export. Optional cross-check against a global.conf and a fit-check of pasted profiles.
These mirror acorn/config.py, acorn/profile.py and acorn/bundle.py. When they disagree, the tools are right and a page is stale — tests/test_config_builders.py guards against that. The accompanying deployment guides are docs/DEPLOYMENT.md and docs/OFFLINE.md in this same repository.
