global.conf builder

global.conf is where an organization sets, once, where every user's machine gets things from — the source repo, the package index, the Python mirror, the editor build, a deployment profile. Everyone who installs from your copy inherits these; your users pass no flags and set no environment variables.

This fills the file in from a form and runs the checks the two installers and acorn config apply. It changes nothing itself.

A standard internet install needs none of this — the built-in defaults are the public repo and pypi.org. Every field below is optional; set only the ones your deployment changes. Leaving a field blank emits its documented default line (or nothing, in plain mode).

Source & location

Where ACORN is installed from and where acorn update-commands fetches updates: a git URL (including self-hosted GitHub/GitLab) or a plain directory path (a copy of this repo on a network drive). Blank = the public GitHub repo.

The folder everything ACORN manages lives in. ~ means the user's home. Put a {user} token in a shared path (C:\acorn\{user}) and each installer expands it to their own login name — that also records a shared_root and turns on the admin-* commands. Blank = ~/acorn.

Offline / internal sources

Blank means "use the internet normally". A directory value is a network share; a URL is an internal mirror. See the offline bundle builder for the air-gapped case.

Where acorn python gets interpreter builds: a mirror URL or a directory of python-build-standalone archives.

Where packages install from: an index URL (Artifactory/Nexus/devpi) or a plain directory of wheels (the internet index is then disabled entirely).

The upload endpoint acorn upload-whls publishes to — usually a different path from the index above.

Leave this blank in the copy you distribute. It's a write credential and every value in this file is seeded into every user's settings — a token here hands your whole fleet publish rights. Set it only on the publishing machine with acorn config set package_upload_token.

Channel acorn forge-install fetches command-line tools from. Blank = conda-forge (the community channel; ACORN never consults Anaconda's defaults).

Trust the OS certificate store for HTTPS — for internal mirrors signed by a machine-installed corporate CA. Alternatively ship the CA in vendor/certs/.

Editor

ACORN_VSCODE_FLAVOR

A licensing choice. Blank = microsoft. Must match the offline bundle's [editor] flavor if you build one.

Where the editor installs extensions from. Blank = the flavor's own default (Marketplace / Open VSX). Setting this on microsoft rewrites product.json in a proprietary binary — prefer switching the flavor to vscodium.

ACORN_VSCODE_EXTENSIONS

Extensions in a fresh editor. Blank = the starter kit for the flavor. Add the literal none to install none.

A folder (relative to this repo copy, or absolute) holding a settings.json / keybindings.json to seed into a fresh editor. Merged over the built-in defaults; only on first install.

Profiles & custom commands

A deployment profile the installer applies instead of the default single dev venv — a single .toml file, or the folder of them (installation-profile), each deciding who it reaches. Relative to this repo copy, or absolute. Build these in the profile builder.

A TOML file declaring your org's own acorn <name> commands. Relative to this repo copy, or absolute.

ACORN_STARTUP_COMMANDS

Custom command names run automatically in every new shell, in order. Each must be declared in the custom-commands file above. Join with && in one entry to chain (stops that chain on failure); commas separate independent entries.

  Reference — what reads this file, and what it can't set
  
install.sh sources it;
  install.ps1 parses it. Both apply it at install time only
  — a value is copied into the user's settings.json once and
  never re-read, so changing global.conf later means users run
  acorn update-commands then re-provision, or set the value with
  acorn config set. An ACORN_<NAME> environment
  variable overrides the matching key for one run.

  
Runtime settings that are not in this file
  (default_base, default_venv, auto_activate,
  update_source, ca_cert, shared_root) are
  either recorded automatically at install time or changed later with
  acorn config set.
