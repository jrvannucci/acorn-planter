Offline bundle builder

offline-bundle.toml declares everything an air-gapped share will hold — the platforms, the interpreters, the wheelhouse, the conda-forge tools, the editor, the build settings. It knows nothing about profiles, on purpose: profiles conform to the bundle, never the reverse.

This fills it in from a form and runs the checks the builder runs. It downloads and builds nothing — that stays GET_STARTED_OFFLINE_BUNDLE/offline-bundler.cmd.

The bundle is a superset: everything that crosses the air gap is inside it, and nothing reaches the closed network any other way. Every field is optional — an empty file builds the default bundle. Build the profiles that install from it in the profile builder.

The bundle

Everything the share contains, plus the settings the build itself needs.

Import an existing offline-bundle.toml

Paste one to load it into the form. Skip to start fresh.

Target platforms

The machines this share serves. The wheelhouse covers all of them at once, but uv, the interpreters and the editor are native binaries — run the build once per platform into the same output folder to stage those. Building on a platform not listed here is an error. Leave all unchecked to accept whatever machine runs the build.

Where the bundle will live on the target machines. Baked into the global.conf the build writes, so users' package_index points at the share, not the folder you built in.

Python interpreters to mirror

Every venv any profile builds comes from one of these. Use major.minor.

Packages (the wheelhouse)

Every distribution any profile may name, plus whatever users should be able to acorn install later. hatchling, ipython, ruff, ipykernel and pip are always bundled — don't list them. PyPI applications like spyder or jupyterlab do belong here. Pin with ==; several pinned versions of one package are allowed.

conda-forge command-line tools (optional)

Non-Python tools — ripgrep, pandoc, ffmpeg, gh. Vendors micromamba and builds a channel so acorn forge-install works offline. Pin conda-style: pandoc=3.2.

[editor]

Flavor — a licensing choice. Staging the official build onto a share is redistribution under Microsoft's terms; VSCodium is MIT + Open VSX. Must match ACORN_VSCODE_FLAVOR in global.conf.

Extensions to stage

Offline, an extension that wasn't staged can't be fetched — so every extension global.conf tells users to install has to appear here too.

Must match ACORN_EXTENSION_GALLERY in global.conf.
