Offline bundle builder

Write offline-bundle.toml — the declaration of everything an air-gapped share will hold — without hand-editing TOML. When it's ready, optionally add the deployment profiles that install from it and check that each one fits.

Nothing here downloads or builds anything. It produces text for two files and runs the same checks acorn does. The build itself stays GET_STARTED_OFFLINE_BUNDLE/offline-bundler.cmd.

The mental model. The bundle is a superset: everything that crosses the air gap is inside it, and nothing reaches the closed network any other way. A deployment profile is a subset — it can only select from what the bundle holds. global.conf carries nothing; it just points each machine at the share. This tool builds the superset first, then (if you want) the subsets.
Step 1 — required

The bundle

Everything the share contains, plus the settings the build itself needs. Every field is optional; an empty file builds the default bundle.

Import an existing offline-bundle.toml

Paste one to load it into the form and see it explained and checked. Skip this to start fresh.

Target platforms

The machines this share serves. The wheelhouse covers all of them at once, but uv, the interpreters and the editor are native binaries — run the build once per platform into the same output folder to stage those. Building on a platform not listed here is an error. Leave all unchecked to accept whatever machine runs the build.

Where the bundle will live on the target machines, e.g. S:\tools\acorn. Baked into the global.conf the build writes, so users' package_index and friends point at the share rather than the folder you built in.

Python interpreters to mirror

Every venv any profile builds comes from one of these. A profile pinning python = "3.11" needs 3.11 here. Use major.minor.

Packages (the wheelhouse)

Every distribution any profile may name, plus whatever users should be able to acorn install later — on a closed network nobody can add one afterward. hatchling, ipython, ruff, ipykernel and pip are always bundled; don't list them. PyPI applications like spyder or jupyterlab do belong here. Pin with ==; several pinned versions of one package are allowed (pandas==2.1.4 and pandas==2.2.3 sit side by side).

conda-forge command-line tools (optional)

Non-Python tools — ripgrep, pandoc, ffmpeg, gh. Vendors micromamba and builds a channel into the bundle so acorn forge-install works offline. Pin with = (conda style): pandoc=3.2.

Editor

Flavor — a licensing choice as much as a technical one. Staging the official build onto a share is redistribution under Microsoft's terms; VSCodium is MIT and pulls extensions from Open VSX. This must match ACORN_VSCODE_FLAVOR in global.conf or the build stops.

Extensions to stage

Offline, an extension that wasn't staged can't be fetched — so every extension global.conf tells users to install has to appear here too, or the build stops. The starter set is shown; edit freely.

Only if you run one. Must match ACORN_EXTENSION_GALLERY in global.conf.

    Step 2 — optional
    
Deployment profiles

    
Each file in installation-profile/ describes an
    environment users end up with, and who gets it. One marked
    default = true reaches everyone; others reach exactly the users
    they list, layered on top. Every name a profile uses must resolve inside the
    bundle above — Step 3 checks that.


    

    
  


  

    
  







  

    Step 3 — optional
    
Fit check

    
The same check acorn profile-check runs on the
    air-gapped side: every Python, package, tool and editor a profile names, matched
    against what the bundle declares it will hold. Fix anything red by adding it to
    the bundle in Step 1.
